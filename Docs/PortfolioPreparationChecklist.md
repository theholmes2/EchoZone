# EchoZone 포트폴리오 준비 체크리스트

작성일: 2026-10-15

게임 기능 개발 외에 진행할 GitHub 정리, 포트폴리오 PPT, 빌드 기반 마이그레이션 검증·촬영, 기술 설명 및 면접 준비를 기록한다. 아래 항목은 앞으로 할 일이며 구현·검증 완료를 뜻하지 않는다.

## 1. 한 컴퓨터에서 빌드로 멀티플레이 테스트하기

- [ ] 현재 프로젝트의 빌드 설정, 온라인 접속 방식, 계정 인증 방식을 확인한다.
- [ ] 에디터 Play Mode가 아닌 빌드 실행 파일 기준으로 따라 할 수 있는 실행 절차를 작성한다.
- [ ] 같은 컴퓨터에서 빌드 인스턴스 여러 개를 실행하고 Host 1명과 Client들을 같은 방에 접속시킨다.
- [ ] 인스턴스별로 서로 다른 플레이어 인증 ID가 필요한지 확인하고, 동일 계정·인증 캐시 충돌을 피하는 실제 방법을 정리한다.
- [ ] 창 모드, 인스턴스 구분, 백그라운드 실행, 로그 분리 방법을 준비한다.
- [ ] 정상 퇴장과 Host 프로세스 강제 종료를 구분해서 테스트한다.
- [ ] Host 이탈 후 새 Host 선출, 재연결, 현재 방 상태 복원을 확인한다.
- [ ] 복원 대상인 월드·플레이어·진행도·타이머·정산 상태를 코드와 기존 검증 문서에서 확인해 테스트 목록으로 만든다.
- [ ] 늦은 참가, 연결 끊김·재접속, 마이그레이션 후 저장·정산, 중복 이벤트도 확인한다.
- [ ] 실행 환경, 재현 순서, 기대 결과, 실제 결과, 미검증 항목을 남긴다.

완료 기준: 빌드 실행부터 Host 강제 종료와 복구 확인까지 혼자 재현할 수 있는 절차 및 테스트 기록이 있다.

## 2. 마이그레이션 테스트 영상 찍기

- [ ] 영상에서 증명할 동작과 촬영 순서를 정한다.
- [ ] Host·Client 역할과 현재 상태를 화면에서 구분할 수 있게 준비한다.
- [ ] Host 종료 전 상태 → Host 강제 종료 → 승격·재연결 → 상태 유지 → 플레이 지속을 촬영한다.
- [ ] 단순 재접속과 실제 상태 복원을 구분할 수 있는 전후 비교 장면을 넣는다.
- [ ] 영상 자막에 검증한 범위와 한계를 명시한다.
- [ ] 인증 토큰, 티켓, 계정 개인정보 등이 화면이나 로그에 노출되지 않는지 확인한다.
- [ ] PPT와 GitHub에서 볼 수 있도록 최종 영상 및 링크를 준비한다.

## 3. 네트워크 구조를 Mermaid로 설명하기

목표: 면접관이 한눈에 사용 기술, 각 구성요소의 역할, 요청 흐름, 저장 위치와 복구 구조를 이해할 수 있게 한다.

용어 메모: 연결 상태·지연 등을 보여 주는 UI는 보통 네트워크 인디케이터라고 부른다. 여기서 준비하려는 것은 네트워크 아키텍처 다이어그램과 시퀀스 다이어그램이다.

- [ ] 실제 코드와 패키지 설정을 조사해 사용한 네트워크·인증·세션·연결·Cloud 서비스와 버전을 확인한다.
- [ ] Mermaid로 Client, Host, 연결 서비스, Cloud 처리, 저장소의 관계를 그린다.
- [ ] 각각의 구성요소가 연결 중계, 게임 판정, 인증, 영속 저장 중 무엇을 담당하는지 표시한다.
- [ ] 접속·인증·방 생성·참가 시퀀스 다이어그램을 작성한다.
- [ ] 게임 요청 → 서버 검증 → 상태 변경 → 복제/이벤트 → 클라이언트 반응 시퀀스를 작성한다.
- [ ] 저장·체크포인트·불러오기·개인 지갑·탈출 정산 흐름을 실제 구현에 맞춰 그린다.
- [ ] Host 이탈 → 승격·재접속 → Snapshot 복원 → 플레이 재개 시퀀스를 작성한다.
- [ ] 현재 Session 상태와 개인 계속하기 데이터의 관계 및 권한을 구분한다.
- [ ] Mermaid 원본과 PPT에 삽입할 읽기 쉬운 도형 이미지를 준비한다.
- [ ] 도식의 각 주장과 구현 코드 위치를 연결한다.

## 4. 기술을 왜 선택했는지 설명하기

각 항목은 문제 → 후보 대안 → 선택 이유 → 구현 방식 → 검증 결과 → 한계 순서로 정리한다. 구현 사실과 설계 의도는 구분한다.

- [ ] 네트워크 라이브러리와 Host 기반 구조를 선택한 이유를 정리한다.
- [ ] 사용한 세션·연결 서비스의 역할과 선택 이유를 정리한다.
- [ ] 직접 RDB를 운영하는 대신 관리형 Cloud 저장·처리를 선택한 이유를 정리한다.
- [ ] Cloud는 DB의 반대 개념이 아니라는 점을 이해하고, 실제 저장 서비스·데이터 구조·접근 권한을 정확히 설명한다.
- [ ] 비용, 개발 규모, 운영 부담, 데이터 관계·조회 요구, 트랜잭션 요구, 서비스 의존성을 비교한다.
- [ ] 데이터와 동시 접속 규모가 커지거나 복잡한 조회가 필요할 때 RDB 또는 별도 백엔드를 검토할 기준을 정리한다.
- [ ] Brick·Glue·Config 분리, 서버 권한, 마이그레이션, 저장·정산에도 같은 설명 형식을 적용한다.

## 5. 해킹·변조·중복 요청 대응 설명하기

- [ ] 실제 적용된 방어와 아직 적용하지 않은 방어를 코드 근거로 구분한다.
- [ ] RPC에서 소유권·거리·생존·행동 조건 등을 어떻게 재검증하는지 확인한다.
- [ ] 클라이언트가 잔액·보상·Snapshot을 임의 확정할 수 있는지와 Cloud 측 검증 경계를 확인한다.
- [ ] 중복 정산, 재시도, 재접속, Host Migration에서 멱등성·Revision/CAS·완료 기록 순서를 설명한다.
- [ ] Host도 플레이어라는 구조적 한계와 악의적인 Host를 어느 범위까지 방어할 수 있는지 정리한다.
- [ ] 비밀값 보관, 인증·인가, 저장 데이터 접근 권한을 확인한다.
- [ ] 공격 예시 → 검증 위치 → 거절·복구 결과 형태의 사례를 준비한다.

## 6. Unity 공식 문서와 근거 붙이기

- [ ] 사용한 기술과 버전에 맞는 Unity 공식 문서를 확인한다.
- [ ] 네트워크 동기화·RPC·권한·연결 서비스·인증·Cloud 저장·Cloud 처리·마이그레이션 관련 문서를 필요한 범위에서 연결한다.
- [ ] PPT와 README의 해당 설명 가까이에 문서 링크를 붙인다.
- [ ] 공식 제공 기능과 프로젝트에서 직접 구현한 기능을 구분한다.
- [ ] 링크 제목, 확인일, 설명을 뒷받침하는 내용을 기록한다.

## 7. GitHub 정리

- [ ] 현재 변경 사항을 기능 변경, 자동 생성 파일, 임시 검증 자료로 구분한다.
- [ ] README에 게임 소개, 담당 범위, 핵심 기능, 기술 스택, 실행 방법을 정리한다.
- [ ] 네트워크 구조, 기술 선택 이유, 마이그레이션 검증 문서와 영상을 연결한다.
- [ ] 소스 구조 및 핵심 코드 진입점을 안내한다.
- [ ] 구현 완료·실제 검증·미검증 범위를 명확히 표시한다.
- [ ] 비밀값과 불필요한 대용량·임시 파일 노출 여부를 검토한다.
- [ ] 공개 범위와 커밋할 파일을 검토한 뒤 정리한다. 커밋·Push·배포는 별도 요청 시 진행한다.

## 8. 포트폴리오 PPT 만들기

- [ ] 대상 직무와 강조할 역량을 정하고 목차를 만든다.
- [ ] 프로젝트 개요, 개발 범위, 핵심 플레이를 짧게 보여 준다.
- [ ] 네트워크 아키텍처와 주요 시퀀스 다이어그램을 배치한다.
- [ ] 문제 해결 사례로 마이그레이션·데이터 복원·저장·정산을 실제 근거에 맞춰 설명한다.
- [ ] 기술 선택 이유, 대안과 트레이드오프, 보안 대응 및 한계를 넣는다.
- [ ] 테스트 결과와 시연 영상, GitHub, Unity 공식 문서 링크를 넣는다.
- [ ] 한 슬라이드에서 전달할 메시지를 좁히고 도형·글자의 가독성을 검토한다.
- [ ] 최종 PPT와 공유용 PDF를 확인한다.

## 9. 면접 대비 공부

- [ ] RDB 기본: 테이블·PK/FK·관계·정규화·JOIN·인덱스·트랜잭션·ACID를 공부한다.
- [ ] RDB와 현재 Cloud 저장 방식의 차이, 동시 수정·일관성·CAS·멱등성을 설명하는 연습을 한다.
- [ ] 네트워크 기본: IP·사설/공인 IP·포트·NAT·라우터·Relay의 역할을 공부한다.
- [ ] TCP/UDP, 지연·지터·패킷 손실·신뢰성·순서 보장의 차이를 공부한다.
- [ ] Host/Client와 전용 서버의 차이, 서버 권한·소유권·RPC·상태 복제를 설명한다.
- [ ] 연결 중계와 권위 있는 게임 서버가 같은 개념인지 구분해서 설명한다.
- [ ] 마이그레이션 중 유실·중복·진행 정지·복구 시점 문제를 설명한다.
- [ ] 왜 이 기술인가, 다른 방법은 무엇인가, 규모가 커지면 어떻게 할 것인가에 대한 답변을 준비한다.
- [ ] 예상 질문과 자신의 코드·도식·영상에 근거한 답변을 문서로 만든다.
