# Relay 마이그레이션 검증 기록

2026-10-01. 기존 변경을 보존했으며 이번 재개에서는 운영 C# 수정·커밋·푸시를 하지 않았다.

## 환경과 방법

- 동일 PC의 Main Editor(A)와 Multiplayer Play Mode 가상 플레이어 B/C, 총 3개 프로세스.
- 실제 Relay 세션에 참가한 뒤 A → B → C 순서로 두 번 호스트를 교체했다. 첫 교체 후 A도 코드로 재입장했다.
- `ForceHostExitForMigrationTestAsync`의 정상 Leave 경로를 사용했다. 프로세스 강제 종료나 인터넷 단절 검증이 아니다.
- RunId `d18256e2753142d89fc017ce3d582ba5` 유지. 두 번째 복원 적용 키의 SnapshotVersion은 127로 확인했다.
- 상태 비교를 위해 런타임에서 HP·장물·수배·재장전 시간 등을 주입했다. 절도/검사 진행 상태 일부는 리플렉션으로 구성한 테스트 조건이다. 사용자 입력부터 시작하는 종단 테스트는 아니다.
- 두 번째 교체에서는 EnemyRuntimeUpdateGlue를 잠시 비활성화하여 복구 직후 전투로 결과가 변하는 것을 막았다. 펫 소유자 참조는 기존 ManualUpdate(0)를 한 번 호출해 확인했다.
- 첫 번째 교체는 복구 후 AI가 진행되어 사망·펫 대기 등의 변화가 섞였다. 이 결과만으로 상태 유실 여부를 판정하지 않았다.

무기 타이머 600초/300초는 복원을 관찰하기 위한 비정상적으로 긴 테스트값이다. 실제 재장전 조작과 애니메이션 검증으로 해석하면 안 된다.
Cloud 세션 체크포인트는 사용했지만 탈출 정산은 실행하지 않았다. 개인 Cloud 잔액을 변경하는 검증은 하지 않았다.

## 아직 미확인

- 실제 호스트 프로세스 강제 종료, 인터넷 단절 및 다른 PC/빌드 조합.
- 사망 후 부활 대기시간이 0보다 큰 상태에서의 실제 Relay 교체.
- 탈출 정산 중 교체와 Cloud SettlementId 영수증 재대조의 실제 통합 경합.
- 같은 Snapshot 재적용 시 런타임 전체 중복 방지 실험.
- 도주 중/수거 대기 펫의 모든 타이머와 회수 경합 조합.
- AI를 계속 실행한 채 장시간 플레이했을 때의 경찰 분포·체감·성능.
- 모든 클라이언트 화면의 UI/애니메이션 시각 검증.

## 종료 상태

- 테스트 클라이언트와 마지막 호스트에 정상 Leave를 요청한 뒤 Main Editor의 Play Mode를 종료했다.
- Main Editor에서 playing=false, scene.isDirty=false, EnemyRuntimeUpdateGlue.enabled=true 확인.
- 테스트 런타임 상태를 씬/프리팹으로 저장하지 않았다. Console은 지우지 않았다.
- 마지막 호스트 Console에는 과거 9월 23일 metadata 오류와 9월 30일 Unity AI Assistant 연결 오류가 있었으나, 이 둘은 이번 게임 마이그레이션 신규 오류로 세지 않았다.
- 전체 프로세스의 모든 과거 로그가 무오류였다고 보장하지 않는다.
- 상세 임시 비교 자료는 Temp/relay-before.json 및 Temp/relay-after.json에 두 번째 교체 기준으로 생성했다. Temp 자료는 Unity가 정리할 수 있다.
